# Recipe Generation with Intelligent Caching

## 🎯 The Problem

Without caching, every recipe generation costs money:
- User 1 generates "Pasta with tomatoes" → $0.005 OpenAI API call
- User 2 generates "Pasta with tomato sauce" → $0.005 OpenAI API call (same recipe!)
- User 3 generates "Spaghetti marinara" → $0.005 OpenAI API call (same recipe!)

**Result**: 3 users, 3 API calls, $0.015 total, generating essentially the same recipe 3 times.

## ✅ The Solution: Intelligent Caching

Our system **checks for similar recipes BEFORE** calling OpenAI:

- User 1 generates "Pasta with tomatoes" → No cache, calls OpenAI ($0.005), **saves as public recipe**
- User 2 generates "Pasta with tomato sauce" → **Finds cached recipe** (85% similar), returns cached (FREE!)
- User 3 generates "Spaghetti marinara" → **Finds cached recipe** (90% similar), returns cached (FREE!)

**Result**: 3 users, 1 API call, $0.005 total, **saving $0.010 (67% cost reduction!)**

## 📊 How It Works

### 1. Cache Lookup Strategy

```python
When user requests recipe:
  1. Normalize ingredients (lowercase, singular, sort)
  2. Compute SHA256 hash of ingredient list
  3. Check for EXACT hash match → Return cached (100% match)
  4. If no exact match:
     - Calculate Jaccard similarity with all cached recipes
     - Find recipes with 80%+ similarity
     - Check preferences match (cuisine, difficulty)
     - Return most similar cached recipe
  5. If no match (< 80% similarity):
     - Generate NEW recipe with OpenAI
     - Save as PUBLIC recipe (available to all users)
     - Future users with similar ingredients benefit!
```

### 2. Similarity Calculation (Jaccard Index)

**Example 1: High Similarity (90%)**
```
User Request: [tomato, pasta, cheese, basil]
Cached Recipe: [tomato, pasta, mozzarella, basil]

Intersection: {tomato, pasta, basil} = 3 ingredients
Union: {tomato, pasta, cheese, basil, mozzarella} = 5 ingredients

Similarity = 3/5 = 0.60 → 60% match
```

Actually, with normalization:
```
User: [tomato, pasta, cheese, basil]
Cached: [tomato, pasta, cheese, basil] (mozzarella normalizes to cheese)

Similarity = 4/4 = 1.00 → 100% match! ✅ Cache hit!
```

**Example 2: No Match (30%)**
```
User Request: [chicken, rice, curry powder]
Cached Recipe: [beef, noodles, soy sauce]

Intersection: {} = 0 ingredients
Union: {chicken, rice, curry, beef, noodles, soy sauce} = 6 ingredients

Similarity = 0/6 = 0.0 → 0% match → Generate new recipe
```

### 3. Cache Storage

When a recipe is generated:

```sql
INSERT INTO recipes (
  ingredient_hash,     -- SHA256 hash for fast lookup
  is_public,           -- TRUE = shared with all users
  is_ai_generated,     -- TRUE = generated by AI
  usage_count,         -- Tracks popularity
  generation_params,   -- Original preferences
  ...
) VALUES (
  'a1b2c3...',
  TRUE,                -- PUBLIC!
  TRUE,
  1,                   -- First use
  '{"cuisine": "Italian", "difficulty": "easy"}',
  ...
);
```

### 4. Usage Tracking

Every time a cached recipe is used:

```sql
UPDATE recipes
SET usage_count = usage_count + 1
WHERE id = 'recipe-id';
```

This helps us:
- Track which recipes are most popular
- Rank suggestions by popularity
- Calculate cost savings

## 🔧 Configuration

### Similarity Threshold

Default: **80%** (recipes must be 80% similar to match)

To adjust:
```python
# app/services/recipe_similarity.py
CACHE_SIMILARITY_THRESHOLD = 0.80  # Change to 0.90 for stricter matching
```

Higher threshold (0.90+):
- ✅ More accurate matches
- ❌ Fewer cache hits

Lower threshold (0.70):
- ✅ More cache hits (save more $$)
- ❌ Less precise matches

**Recommendation**: Keep at 0.80 for best balance

### OpenAI Model

```python
# app/services/openai_client.py
self.model = "gpt-4-turbo-preview"  # Expensive but high quality

```

- GPT-4 Turbo: ~$0.005-0.01 per recipe
- GPT-3.5 Turbo: ~$0.001-0.002 per recipe

### 2. Track Cost Savings in Analytics

```python
# Save to analytics

analytics.track('recipe_cache_effectiveness', {
  'hit_rate': cache_stats['cache_hit_rate'],
  'cost_saved': cache_stats['estimated_cost_saved_usd']
})
```

### 3. Periodically Clean Up Unused Recipes

```sql
-- Delete recipes with zero usage after 30 days
DELETE FROM recipes
WHERE is_public = TRUE
  AND usage_count = 0
  AND created_at < NOW() - INTERVAL '30 days';
```

### 4. Consider User Feedback

```python
# If user rates recipe poorly, don't use it for caching
if rating < 3:
    recipe.is_public = False  # Remove from cache pool
    db.commit()
```
